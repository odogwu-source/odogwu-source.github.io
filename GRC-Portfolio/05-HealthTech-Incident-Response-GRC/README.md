# HealthTech Systems — Incident Response & GRC

## Project Overview
This educational GRC simulation models incident-response governance for a healthcare technology environment. The project demonstrates how critical assets, security incidents and ISO/IEC 27001:2022 controls can be documented and linked to support governance, risk management, operational resilience and audit readiness.

> **Portfolio note:** This is an educational/practice simulation. The control statements and scenarios are used for skills demonstration and are not presented as a production compliance assessment.

## Scenario
HealthTech Systems depends on critical patient-care technology and sensitive health information. The simulated environment required identification of critical assets, documentation of realistic cyber incidents, and implementation of controls covering preparation, detection, response, evidence preservation, recovery and lessons learned.

## Work Performed
- Classified critical healthcare systems and data assets.
- Documented ransomware, phishing/account-compromise and patient-data breach scenarios.
- Assigned incident severity, status and accountable response owners.
- Mapped incident-response activities to ISO/IEC 27001:2022 Annex A controls.
- Documented detection, containment, evidence preservation, continuity, backup/recovery and post-incident review controls.
- Maintained an incident register and supporting evidence trail.

## Incident Scenarios
| Scenario | Type | Severity | Initial Status |
|---|---|---|---|
| Ransomware encrypting critical patient systems and disrupting services | Security | Critical | Investigating |
| Unauthorized access exposing patient personal and health information | Data Breach | Critical | Investigating |
| Phishing compromise leading to unauthorized employee-account access | Phishing | High | Investigating |

## ISO/IEC 27001:2022 Control Mapping
| Reference | Portfolio Control | Purpose |
|---|---|---|
| A.5.24 | Ransomware Detection and Incident Response Procedure | Incident-management preparation and planning |
| A.5.25 | Security Incident Detection and Monitoring | Assessment and decision-making on security events |
| A.5.26 | Incident Containment, Eradication and Response | Response to information-security incidents |
| A.5.27 | Post-Incident Review and Lessons Learned | Learning from information-security incidents |
| A.5.28 | Collection and Preservation of Incident Evidence | Evidence collection and preservation |
| A.5.30 | ICT Continuity and Recovery During Security Incidents | ICT readiness for business continuity |
| A.8.13 | Secure Backup and Restoration of Critical Systems | Information backup |
| A.8.15 | Security Event Logging and Incident Investigation | Logging |

## Critical Assets Demonstrated
The evidence set includes critical healthcare assets such as the Electronic Health Record (EHR) system, Patient Clinical Database and Laboratory Information Management System (LIMS). Their critical classification reflects the potential confidentiality, integrity, availability, patient-safety and operational impact of compromise.

## Key Takeaway
Effective incident-response governance is more than reacting to alerts. It requires defined ownership, critical-asset awareness, repeatable response procedures, defensible evidence, continuity planning and a feedback loop that turns incidents into control improvements.
